# Развёртывание на Render (без собственного домена)

Схема: сайт (статический) и API (Docker) на адресах `*.onrender.com`, база Postgres на Render.
Браузер обращается только к адресу сайта: запросы `/api/...` Render проксирует на API. Так сайт
и API выглядят для браузера как один сайт, и вход работает без своего домена (иначе cookie
сессии не доходила бы до API, потому что поддомены onrender.com считаются разными сайтами).

## Что понадобится

- Аккаунт на render.com.
- Проект в репозитории GitHub, GitLab или Bitbucket (файл `render.yaml` лежит в корне).
  Файл `.env` в репозиторий **не** коммитьте.
- Придумайте логин, email и пароль суперадмина (пароль не короче 8 символов, с буквами и цифрами).

## Шаги

1. **Загрузите проект в репозиторий.** В корне должны лежать `render.yaml`, `backend/`, `frontend/`.
2. **Создайте Blueprint.** Render → New → Blueprint → выберите репозиторий и ветку. Render прочитает
   `render.yaml` и покажет три ресурса: базу `showcase-db`, API `univ-showcase-api`, сайт `univ-showcase`.
3. **Введите секреты.** Render запросит `SUPERUSER_USERNAME`, `SUPERUSER_EMAIL`, `SUPERUSER_PASSWORD`.
   Это ваш будущий суперадмин. Нажмите Apply.
4. **Дождитесь сборки** (первая сборка API 3–6 минут). Статус Live у всех трёх ресурсов.
5. **Проверьте адрес API.** Откройте `univ-showcase-api` в панели: адрес вверху. Если это
   `https://univ-showcase-api.onrender.com`, ничего менять не нужно. Если в имени появился суффикс
   (имя было занято), откройте сайт `univ-showcase` → Redirects/Rewrites и поправьте destination правила
   `/api/*` на ваш адрес со `/*` в конце. Тот же адрес поправьте в `render.yaml`, чтобы не потерять при
   повторном применении.
6. **Проверьте API:** `https://<адрес-API>/health` должен ответить `{"status":"healthy"}`.
7. **Откройте сайт** `https://univ-showcase.onrender.com` (или ваш адрес). На главной должны быть факультеты
   и карточки, а поиск «нужен робот» найти разработки.
8. **Войдите** суперадмином (логин и пароль из шага 3) и заведите администраторов факультетов:
   Администрирование → Пользователи.

### Нейросеть (по желанию)

Без ключа работает запасной поиск по словам. Чтобы включить нейросеть: API-сервис → Environment →
добавьте `AI_API_KEY` (ключ с https://openrouter.ai/keys) → Save. Сервис перезапустится.

## Что проверить после запуска

| Проверка | Ожидание |
|---|---|
| Войти и обновить страницу (F5) | Вы остаётесь в аккаунте. Если выбрасывает на вход, см. «Если что-то не так» |
| Загрузить обложку в карточку, подождать перезапуска | Изображение на месте (хранится в базе) |
| Открыть сайт после простоя | Первая загрузка до минуты, дальше быстро |
| Оставить заявку на карточке | Заявка видна администратору факультета |

## Ограничения бесплатного тарифа

- Сервис засыпает после 15 минут без запросов, первый запрос после этого идёт около минуты. Перед
  показом откройте сайт за 1–2 минуты и пролистайте главную, чтобы разбудить API и базу. На время
  защиты можно перевести API на платный тариф Starter, это около 7 долларов в месяц.
- Бесплатная база Postgres удаляется через 30 дней после создания, после 14 дней отсрочки данные теряются.
  Создавайте её незадолго до защиты или переведите на платный тариф. Резервная копия:
  `pg_dump "<External Database URL>" > backup.sql` (адрес в панели базы, раздел Connections).
  Восстановить: `psql "<External Database URL>" < backup.sql`.
- Оперативной памяти у бесплатного сервиса 512 МБ: приложению этого достаточно, но тяжёлые операции
  не добавляйте.
- Цены и условия Render меняются, актуальные смотрите на render.com/pricing.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| Сайт открывается, но данных нет, в консоли браузера ошибки 404 или 502 на `/api/...` | Неверный destination правила `/api/*` или API ещё просыпается. Проверьте шаг 5 и подождите минуту |
| После F5 выбрасывает на страницу входа | Не доходит cookie сессии. Проверьте, что у API задано `REFRESH_COOKIE_PATH=/api/users`, а у сайта `VITE_API_BASE_URL=/api`, и что сайт открыт по `https`. Если всё верно, а Render не передаёт `Set-Cookie` через rewrite, нужен собственный домен с двумя поддоменами |
| Изображения пропадают после перезапуска | Не задан `MEDIA_STORAGE=db` у API |
| Ошибка сборки сайта про версию Node | Задайте у сайта `NODE_VERSION=20` |
| API не стартует, в логах ошибки базы | Проверьте, что `DATABASE_URL` взят из базы `showcase-db` (внутренний адрес) |
| «Слишком много запросов» у разных людей одновременно | Ограничения считаются по адресу клиента из `X-Forwarded-For`; если прокси Render его не передаёт, все посетители выглядят как один |
| Хочу создать суперадмина заново | Суперадмин создаётся один раз при пустой базе. Смените пароль в разделе профиля или пересоздайте базу |

## Что отличается от локального запуска

| | Локально (docker compose) | Render |
|---|---|---|
| Изображения | Файлы на диске | В базе (`MEDIA_STORAGE=db`) |
| Адрес API | `http://localhost:8000` | `/api` на адресе сайта (прокси) |
| Cookie сессии | `Path=/users` | `Path=/api/users` |
| Демо-аккаунты | Создаются | Не создаются, только суперадмин из переменных |
| HTTPS | Нет | Есть, выдаёт Render |
