# Архитектура

## Модель данных

```
faculties ──< cards >── card_tags ──< tags
    │           │
    │           └──< inquiries
    └──< users (admin: faculty_id)           media_files (изображения карточек)
```

| Таблица | Назначение |
|---|---|
| `faculties` | Факультеты. Создаёт суперадмин |
| `users` | Аккаунты. `role`: `user`, `admin`, `superuser`. У `admin` обязателен `faculty_id` |
| `cards` | Карточки разработок: `faculty_id`, название, краткое и подробное описание, `status` (`draft`, `published`), `readiness`, обложка и галерея (id из медиатеки), контакты |
| `tags`, `card_tags` | Справочник тегов (нижний регистр, уникальны) и связь «многие ко многим» |
| `inquiries` | Заявки на сотрудничество: `status` (`new`, `in_progress`, `done`), автор заявки, если он вошёл |
| `media_files` | Загруженные изображения; на диске лежат под сгенерированным именем |
| `refresh_tokens` | Хеши refresh-токенов |

## Права

| Действие | Гость | Пользователь | Админ факультета | Суперадмин |
|---|---|---|---|---|
| Смотреть опубликованное, искать, оставлять заявку | да | да | да | да |
| Видеть черновики | нет | нет | своего факультета | все |
| Создавать и править карточки | нет | нет | своего факультета | любого |
| Публиковать, скрывать, удалять карточки | нет | нет | своего факультета | любого |
| Разбирать заявки | нет | нет | по своим карточкам | все |
| Загружать изображения | нет | нет | да | да |
| Создавать факультеты, управлять пользователями и тегами | нет | нет | нет | да |

Правила собраны в `backend/app/permissions.py` (чистые функции с тестами), а роутеры вызывают
их при каждом обращении. Админ не может подменить факультет в запросе: `resolve_card_faculty`
возвращает отказ, а не молча заменяет значение. Администратор без факультета получает 403 на любые
операции сотрудника (`auth.require_staff`).

## API

| Метод и путь | Доступ |
|---|---|
| `GET /faculties`, `GET /faculties/{id}` | все |
| `POST/PUT/DELETE /faculties…` | суперадмин |
| `GET /tags` | все (теги опубликованных карточек с числом карточек) |
| `DELETE /tags/{id}` | суперадмин |
| `GET /cards?q=&faculty_id=&tag=&readiness=&skip=&limit=` | все (только опубликованные) |
| `GET /cards/{id}` | опубликованная: все; черновик: сотрудники факультета |
| `GET /cards/manage`, `GET /cards/manage/stats` | сотрудники (свой факультет или все) |
| `POST /cards`, `PUT /cards/{id}`, `PUT /cards/{id}/status`, `DELETE /cards/{id}` | сотрудники факультета карточки |
| `POST /cards/{id}/inquiries` | все, не более 5 заявок в час с одного адреса, скрытое поле-ловушка для ботов |
| `GET /inquiries`, `PUT /inquiries/{id}/status`, `DELETE /inquiries/{id}` | сотрудники факультета карточки |
| `POST /ai-search/` | все, не более 10 запросов в минуту |
| `POST /media`, `GET /media`, `DELETE /media/{id}`, `GET /media/{id}/file` | загрузка и список: сотрудники; сам файл: все |
| `GET /admin/stats`, `GET/POST /admin/users`, `PUT/DELETE /admin/users/{id}` | суперадмин |
| `POST /users/register`, `/users/login`, `/users/refresh`, `/users/logout`, `GET/PUT /users/me` | по назначению |
| `/mcp` | MCP-сервер каталога, только чтение опубликованного |

Полная интерактивная документация: `/docs`.

## Поиск

**Каталог** (`GET /cards?q=`) ищет строго: слова запроса с учётом окончаний, веса полей. Без словаря связанных понятий,
чтобы фильтр вёл себя предсказуемо.

**Подбор по смыслу** (`POST /ai-search/`):

1. `ai_search.py` формирует запрос к нейросети: системная инструкция, список факультетов и самые частые теги каталога,
   запрос пользователя. Инструмент `search_cards(keywords, faculty)` работает по тому же поисковому ядру.
2. Цикл вызова инструмента (до 5 шагов): нейросеть расширяет запрос смежными понятиями и вызывает поиск несколько раз.
3. Ответ в JSON: `message`, `terms`, `results[{card_id, reason}]`. Роутер оставляет только существующие опубликованные
   карточки и возвращает их с пояснениями.
4. Сбой провайдера или отсутствие ключа переключают на `keyword_search()`: основы слов, веса полей и словарь
   связанных понятий (`SYNONYM_CLUSTERS` в `search.py`, его можно дополнять).

Ядро поиска (`search.py`):
- слова от шести букв сводятся к первым пяти (робот, роботов, робототехника → «робот»);
- вес совпадения: теги 3, название 2,5, краткое описание 1,5, факультет и текст по 1;
- бонус за совпадение всех слов запроса; связанные понятия весят вдвое меньше прямых;
- результат без единого совпадения в выдачу не попадает.

## Безопасность

- Пароли: bcrypt; блокировка аккаунта на 15 минут после 5 неверных входов; ограничения частоты на вход,
  регистрацию, заявки и ИИ-поиск.
- Сессии: короткий access-токен (в памяти браузера) и refresh-токен в httpOnly cookie, на сервере хранится только его хеш.
- Роль и факультет берутся из базы при каждом запросе, а не из токена: смена прав действует сразу.
- Описание карточки (HTML) пересобирается белым списком тегов, ссылки проверяются; скрипты, `on*`-атрибуты и
  `javascript:` не проходят.
- Загрузка: тип изображения определяется по байтам файла, имя на диске генерируется сервером, лимит размера,
  файлы отдаются с `nosniff` и ограничивающим CSP.
- Заявки: валидация, лимит частоты, ловушка для ботов.
- CORS с явным списком адресов, заголовки безопасности и CSP в nginx.
