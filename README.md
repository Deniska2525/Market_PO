# Витрина разработок вуза

Веб-платформа, где вуз показывает свои разработки, проекты и технологии, а компании и
заказчики находят нужные и оставляют заявки на сотрудничество. Главная особенность —
**контекстный поиск**: человек описывает задачу обычными словами («нужен робот для склада»),
а система находит разработки, которые называются иначе (например, «компьютерное зрение»
на факультете кибернетики) и объясняет, почему они подходят.

## Роли и сценарии

| Роль | Что может |
|---|---|
| **Посетитель** (без входа) | Искать разработки (в том числе нейросетью), смотреть каталог и карточки, оставлять заявки |
| **Пользователь** (после регистрации) | То же; в заявке подставляются его имя и email |
| **Администратор факультета** | Добавлять, редактировать, публиковать и удалять карточки **только своего факультета**, загружать изображения, разбирать заявки по своим карточкам |
| **Суперадмин** | Всё то же для всех факультетов, а также создавать и удалять факультеты, заводить аккаунты администраторов и назначать им факультет, управлять тегами |

Факультет администратору назначает суперадмин при создании его аккаунта. Публичная регистрация
всегда создаёт обычного пользователя. Все ограничения проверяются на сервере, интерфейс лишь
прячет недоступные действия: администратор другого факультета получит отказ и при прямом
обращении к API.

**Карточка** содержит: факультет, название, краткое описание, подробное описание (форматированный
текст), теги, уровень готовности (идея, прототип, пилот, готово к внедрению), обложку и галерею,
контакты и сайт. Черновики видят только сотрудники факультета.

## Как работает контекстный поиск

1. Нейросеть получает запрос, список факультетов и тегов каталога и **сама вызывает инструмент
   поиска** несколько раз с разными формулировками: сам запрос, связанные технологии, смежные области.
2. Из найденного она выбирает лучшие карточки и пишет, чем каждая полезна («на факультете кибернетики
   есть разработка по компьютерному зрению, без неё робот не увидит окружающий мир»).
3. Нейросеть ничего не выдумывает: сервер проверяет каждый id по базе, неизвестные и
   неопубликованные карточки отбрасываются.
4. Если ключа нет или провайдер недоступен, включается **запасной режим** без внешних сервисов:
   поиск по словам с учётом окончаний, весами полей (теги важнее описания) и словарём связанных
   понятий. Он слабее нейросети, но демонстрацию не ломает.

Подробности в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Стек

Backend: Python, FastAPI, SQLAlchemy, PostgreSQL 16, JWT (access + refresh в httpOnly cookie), bcrypt,
slowapi, OpenAI-совместимый клиент (OpenRouter, Groq, Gemini), MCP-сервер для внешних ИИ-агентов.
Frontend: Vue 3, Vite, Pinia, Vue Router, Axios. Запуск: Docker Compose (nginx раздаёт фронтенд).

## Быстрый запуск локально

Нужны Docker с Compose и свободные порты 80, 8000, 5432 (все привязаны к 127.0.0.1).

```bash
cp .env.example .env
# впишите SECRET_KEY (команда для генерации есть в файле) и, по желанию, пароли демо-аккаунтов и AI_API_KEY
docker compose up --build -d
docker compose logs -f backend        # дождитесь строки про запуск uvicorn
```

Откройте `http://localhost`. Документация API: `http://localhost:8000/docs`.

Демо-аккаунты (создаются при первом запуске на пустой базе):

| Логин | Роль | Пароль |
|---|---|---|
| `superuser` | суперадмин | `SEED_ADMIN_PASSWORD` |
| `admin_cyber` | администратор факультета кибернетики | `SEED_ADMIN_PASSWORD` |
| `admin_bio` | администратор факультета биотехнологий | `SEED_ADMIN_PASSWORD` |
| `anna` | пользователь | `SEED_USER_PASSWORD` |

Если пароли не заданы в `.env`, действуют пароли по умолчанию из `backend/app/university_seed.py` —
они публичные, поэтому задайте свои.

Что попробовать: на главной введите «нужен робот для склада» (без ключа нейросети включится
запасной режим и всё равно найдёт карточку по компьютерному зрению); войдите как `admin_cyber` и
убедитесь, что виден только факультет кибернетики; как `superuser` создайте факультет и администратора.

### Размещение на хостинге

Пошаговая инструкция для Render (бесплатный тариф, без собственного домена): [docs/RENDER.md](docs/RENDER.md),

### Обновление со старой версии (маркетплейс ПО)

Структура данных изменилась. Самый чистый путь: `docker compose down -v` и запуск заново (база
создастся и заполнится заново). Если база нужна: старые таблицы остаются нетронутыми и не
используются, пользователи прежних ролей `developer` и `manager` становятся обычными, а прежние
администраторы без факультета не смогут работать, пока суперадмин не назначит им факультет.

## Структура

```
backend/app/
  models.py, schemas.py        модели БД и схемы API
  permissions.py               права по ролям и факультетам (чистые функции)
  search.py, taxonomy.py       поиск без нейросети, нормализация тегов
  sanitize.py, uploads.py      очистка HTML, проверка загружаемых файлов
  ai_search.py                 подбор нейросетью и запасной режим
  university_seed.py           факультеты, демо-карточки и демо-аккаунты
  routers/                     users, admin, faculties, tags, cards, inquiries, ai_search, media
  mcp_tools.py                 MCP-сервер каталога для внешних ИИ-агентов
backend/tests/                 автотесты чистой логики
frontend/src/
  views/                       страницы (каталог, карточка, управление, администрирование)
  components/, composables/    переиспользуемые элементы, уведомления и окна
  stores/, services/, utils/   состояние, обращения к API, функции с тестами
docs/                          архитектура и развёртывание
```

## Проверки

```bash
cd backend && python -m unittest discover -s tests -v       # 29 тестов: права, поиск, теги, очистка HTML, загрузки
cd frontend && node --test src/utils/*.test.mjs             # 16 тестов: уведомления, форматирование, ошибки
```

Тесты не требуют установленных зависимостей. Роутеры, база и интерфейс проверяются вручную по сценариям выше.

## Что не реализовано

Уведомления по email (заявки видны в кабинете), оплата, антивирусная проверка загрузок, миграции схемы
через Alembic (используется `schema_sync.py`, который добавляет недостающие колонки), автоматические
тесты API и интерфейса. Список мер безопасности и чек-лист публикации в интернет: [docs/DEPLOY.md](docs/DEPLOY.md).
